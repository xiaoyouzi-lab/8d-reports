## 二、语言切换 (i18n)

### 架构

- 框架：`next-intl` v4（原生支持 Next.js App Router + Server Components）
- 模式：Cookie-based locale（不使用 URL 前缀，保持 URL 干净）
- 语言：`en` (英文) / `zh-CN` (简体中文)
- 默认：首次访问检测 `Accept-Language` header，未匹配则回退到 `en`

### 新增文件

```
src/
  i18n/
    request.ts          ← next-intl 服务端请求配置
    routing.ts          ← locale 检测 + cookie 操作逻辑
  messages/
    en.json             ← 英文字典
    zh-CN.json          ← 中文字典
  components/
    LangSwitcher.tsx    ← 右上角 中/En 切换按钮
  middleware.ts         ← 根中间件（locale cookie 检测）
```

### 改造文件

| 文件 | 变更 |
|------|------|
| `src/app/layout.tsx` | 包裹 `NextIntlClientProvider`，动态获取 messages |
| `src/app/(marketing)/layout.tsx` | 同 layout 改造 |
| `src/app/(auth)/layout.tsx` | 同 layout 改造 |
| `src/app/(app)/layout.tsx` | 同 layout 改造 |
| **所有组件** (`*.tsx`) | 硬编码文本 → `useTranslations()` hook |
| `src/lib/report-steps.ts` | 步骤标签/描述改为函数（接受翻译函数参数） |
| `src/lib/pdf-export.ts` | 导出文本改为接收翻译参数 |

### 翻译覆盖清单

- 报告编辑器：D0-D8 所有步骤标签、字段标签、占位符、状态徽章
- 分享页：标题、步骤描述、附件提示
- Toast 通知："Saved"/"Failed"/"Link copied" 等

## 三、附件上传

### 上传入口位置

D2 (描述问题), D3 (围堵措施), D5 (验证永久措施), D6 (实施验证), D7 (预防措施)

每个步骤底部，表单字段之后，增加附件区域：两个按钮 + 已上传列表。

### 按钮设计

```
┌─────────────────────────────────────────┐
│  Attachments                            │
│  📷 Take Photo    🖼️ Photo Library      │
│  📎 Upload File                         │
│                                         │
│  📄 defect_top_view.jpg       34 KB  ✕  │
│  📄 measurement_report.pdf  156 KB  ✕  │
│  📄 before_after_comparison.jpg  89 KB ✕ │
└─────────────────────────────────────────┘
```

- 照片按钮在手机上调用 `capture="environment"` 打开相机
- 照片按钮在电脑上等同于文件选择器（`accept="image/*"`）
- 文件按钮：`accept=".pdf,.xlsx,.xls,.docx,.doc,.csv,.txt,.zip"`
- 每个附件右侧有删除按钮 (✕)
- 照片缩略图直接显示，文件显示类型图标 + 文件名 + 大小

### 大小限制

| 计划 | 单文件上限 | 每报告附件数上限 | 总容量上限 |
|------|:--------:|:-----------:|:--------:|
| Free | 5 MB | 10 | 25 MB |
| Pro  | 10 MB | 30 | 100 MB |

（当前 MVP 仅有 Free 用户，先按 Free 限制实现，后续 Pro 表数据可配置）

### 技术架构

```
[前端 PhotoUpload 组件]
  ├─ 拍照 → <input capture="environment" accept="image/*">
  ├─ 相册 → <input accept="image/*">
  └─ 文件 → <input accept=".pdf,.xlsx,.xls,.docx,.doc,.csv,.txt,.zip">
       
[前端处理]
  ├─ 校验：格式 + 大小 (≤5MB)
  ├─ 生成唯一文件名：${reportId}/${stepId}/${uuid}.${ext}
  └─ POST /api/upload → 获取预签名 PUT URL

[API /api/upload]
  ├─ 验证用户登录态
  ├─ 检查配额（已有附件数 + 总量）
  ├─ 生成 S3 预签名 URL (PUT, 5分钟有效期)
  └─ 返回 { presignedUrl, storagePath, publicUrl }

[前端上传]
  └─ PUT presignedUrl (直接到 R2，不经服务器)

[前端保存]
  └─ POST /api/reports/[id]/attachments → 写入 attachments 表
```

### 新增依赖

```
@aws-sdk/client-s3          ← S3 客户端（R2 兼容 S3 API）
@aws-sdk/s3-request-presigner  ← 生成预签名 URL
```

### 新增 API 路由

```
POST   /api/upload                  ← 生成预签名 URL
GET    /api/reports/[id]/attachments   ← 获取附件列表
POST   /api/reports/[id]/attachments   ← 保存附件记录
DELETE /api/reports/[id]/attachments   ← 删除附件（及 R2 文件）
```

### 新增文件

```
src/lib/r2.ts                    ← R2 客户端 + 预签名 URL 生成 + 文件删除
src/components/report/AttachmentArea.tsx   ← 附件区域组件
src/components/report/AttachmentItem.tsx   ← 单个附件条目（缩略图/图标 + 名称 + 大小 + 删除）
```

## 四、导出升级

### Word (.docx) 导出

使用 `docx` 库，服务端生成。

**封面：**
- 公司 Logo（如果已设置）→ 左上角 40mm 宽
- 标题："8D Report"（标题）
- 报告编号
- 日期
- 免费版水印："SAMPLE REPORT" 灰色斜体

**正文：**
- D0-D8 每个步骤标题（一级标题）→ 内容（每个字段的标签 + 值）
- 5-Why 表格（D4）→ 渲染为 Word 表格
- 照片字段 → 如果有附件图片，嵌入 Word

**附件清单（末尾）：**
- 表格列出所有附件：文件名、类型、大小

### Zip 打包

当报告有附件时，导出为 .zip：

```
QR-2025-1084_8D.zip
├── QR-2025-1084_8D_Report.pdf (或 .docx)
└── attachments/
    ├── photo_001.jpg
    ├── test_report.pdf
    └── ...
```

实现：使用 `jszip` 库，客户端打包。

**流程：**
1. 先生成 PDF/DOCX → 得到 Blob（客户端 jsPDF 已是 Blob；DOCX 需通过 API 生成返回 Blob）
2. 检测是否有附件 → 如果没有，直接下载单文件
3. 如果有附件 → 创建 JSZip 实例
   - 添加报告文件
   - 遍历附件，fetch 每个附件的 public URL → 添加为 `attachments/文件名`
4. 生成 zip Blob → 触发浏览器下载

### DOCX 导出 API

```
POST /api/reports/[id]/export/docx
Body: { logoUrl?: string, watermark: boolean, locale: string }
Response: application/vnd.openxmlformats-officedocument.wordprocessingml.document
```

### ExportButton 改造

从单一按钮变为下拉菜单：

```tsx
<DropdownMenu>
  <DropdownMenuTrigger>
    <Button><FileDown /> Export</Button>
  </DropdownMenuTrigger>
  <DropdownMenuContent>
    <DropdownMenuItem onClick={handleExportPdf}>PDF</DropdownMenuItem>
    <DropdownMenuItem onClick={handleExportDocx}>Word (.docx)</DropdownMenuItem>
  </DropdownMenuContent>
</DropdownMenu>
```

### 新增依赖

```
docx          ← Word 文档生成
jszip         ← ZIP 打包
file-saver    ← 浏览器下载（类型安全封装）
```

### 新增文件

```
src/lib/word-export.ts           ← DOCX 生成逻辑
src/lib/export-zip.ts            ← ZIP 打包逻辑
src/app/api/reports/[id]/export/docx/route.ts  ← DOCX 导出 API
src/components/report/ExportMenu.tsx  ← 导出下拉菜单（替代 ExportButton）
```

## 五、公司 Logo 上传

### 入口

- 报告编辑器顶部区域（Share 按钮旁边）小齿轮图标，点开 Settings 弹窗
- 设置弹窗中有 Logo 上传区域
- 也作为 User Settings 的一部分（未来）

### 存储

- 路径：`logos/${userId}/company-logo.${ext}`
- R2 存储，前端缓存 URL
- `publicUrl` 存储在 `users` 表新增 `logoUrl` 字段？或在 `metadata` JSONB 中

### 使用

- 导出 PDF 时：`doc.addImage(logoUrl, 'PNG', margin, margin, 40, ...)`
- 导出 DOCX 时：`ImageRun` 从 URL fetch 图片数据嵌入

### Schema 变更

`users` 表新增字段：
```
logoUrl: text("logo_url")
```

### 新增 API

```
POST /api/user/logo   ← 上传 Logo（multipart 或预签名 URL）
GET  /api/user/logo   ← 获取当前 Logo URL
```

## 七、风险评估

| 风险 | 缓解 |
|------|------|
| `next-intl` 升级导致路由破坏 | 使用稳定版 v4，仅 cookie 模式，不碰路由 |
| R2 预签名 URL 过期太快 | 设为 5 分钟，前端上传 pipeline 不阻塞 |
| 翻译覆盖遗漏 | 先完成所有 label/button/toast 文本提取，再生成 message JSON |
| DOCX 库排版与 PDF 不一致 | 保持简单：标题+内容+表格，不追求像素级对齐 |
| ZIP 打包大附件内存溢出 | 单个附件 ≤10MB，前端 Blob 内存可控 |
